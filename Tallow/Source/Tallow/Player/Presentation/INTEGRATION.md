# Opt-in generated player presentation

`UTallowPlayerPresentationComponent` creates its own transient owner-only partial skeletal mesh. It never replaces Manny, changes a character/controller/Blueprint, loads an asset by guessed path, searches mesh names, changes candle state, runs gameplay timers, or reports lesson success. Nothing enables it automatically.

After the player's camera, held candle and visible flame primitive are registered, call:

1. The verified UE import faces -Y with lateral +X at zero rotation. Default `HandsRelativeTransform` is camera-relative forward20/right0/down110cm, yaw+90° and unit scale. This maps the imported Relight hand_r bone (23,-20,87)cm to (20,23,87)cm before translation, aligning forward with camera+X. Use `UpdateHandsTransform` for further grip corrections; do not alter the source FBX or rig to compensate. Set `PresentationFieldOfView=90`, `PresentationScale=0.6` (defaults).
2. `EnablePresentation(Camera, GeneratedPartialSkeletalMesh, ActualHeldCandlePrimitive, ActualVisibleFlamePrimitive)`. All components must belong to this actor. Pass the render mesh of the flame, not its actor component or point light. Enabling fails before touching projection if references are invalid/unregistered, identical prop primitives, incompatible configuration or another enabled player-presentation component exists on the owner.
3. Call `SetPresentationPose(GeneratedClip, TimeSeconds)`. This samples a clip on the exact custom skeleton with notify delivery disabled and automatic animation ticking off. Exported frame18 is approximately0.566667seconds. Caller can supply successive times for a transition, or sample the hold pose after a gameplay success. Clips are Rest/Hold/Cup/Interact/Relight; seated full-body scene uses its own cinematic actor. No success inference or sequencing is implemented here.
4. `DisablePresentation()` when leaving the opt-in review/game mode. Deactivate, EndPlay and component destruction also release it. The owned partial mesh is destroyed. Camera FP switches/FOV/scale and candle/flame primitive classifications return to their captured values. Values explicitly changed by another caller while enabled are not overwritten when distinguishable. One presentation owner per actor/camera avoids conflicting leases.

World camera FOV is untouched (70° for the current review). All three visible elements use `FirstPerson` primitive projection. Their shared camera90° FP view and0.6 scale preserve relative screen alignment; no held-candle offsets, flame deformation or light settings are changed. Existing owner-only Manny visibility is deliberately the caller's explicit integration responsibility; otherwise two presentations can overlap. Call `UpdateHandsTransform` for camera-space alignment corrections.

Engine visual gates remain: verify import facing/height, actual prop grip, cup clearance, near clipping, same camera scale for flame/candle/hands, no duplicate old FP mesh, and disable/respawn restoration. The lifecycle automation `Tallow.Presentation.Player.ProjectionLifecycle` checks projection lease restoration, repeated teardown, scope destruction and preservation of subsequent caller adjustments without requiring imported assets. It does not claim real camera rendering or skeletal animation was tested. Root owns compilation, automation execution and Unreal visual validation.

### Editor production-adapter fixture

In PIE or editor Standalone on a saved `/Game/Presentation/Maps/Lvl_PlayerContactReview_*` map, run `Tallow.Presentation.PlayerFixture`. This editor-only command spawns a transient camera actor at `(0,0,110)` cm, the actual candlestick at camera `(45,26,-30)`, a wick at its mesh bounding maximum Z, standalone flame, and this production adapter with the imported generated partial. The view target is the fixture itself, preserving `OnlyOwnerSee`; only the controller's default pawn is hidden. Existing review props remain visible, so use a fresh review map with lighting and no duplicate hand/candle actors.

Run `Tallow.Presentation.PlayerPose Hold`, `Cup`, `Interact`, `Relight` or `Rest` to sample the clip at `17/30` seconds. Run `Tallow.Presentation.PlayerFixture off` to restore the previous view target and pawn visibility and destroy the fixture. Re-running creation first removes the previous fixture. The commands refuse other map packages, accept the corresponding PIE package prefix, require an actual player controller, and do not save assets or modify gameplay. They are excluded from non-editor builds. Compilation and actual viewport proof belong to the root integration pass.

Pose evaluation now calls `TickAnimation(0,false)` before `RefreshBoneTransforms`, because UE's `SetPosition` updates single-node time but does not perform component evaluation. The owned hands suppress notify dispatch throughout their lifetime.

### Generated partial culling envelope

`HandsBoundsScale` defaults to 3 (finite range 1–10, applied on enable). Actual engine diagnostics showed constant bounds centered `(25.258,0,40.480)` cm with extent `(11.389,33.969,40.480)` while Cup wrists reached world Z=98.376 cm and Interact reached X=49 cm. Those animated joints lie outside the imported bounds; merely refreshing bones/bounds did not update the envelope. The 3x envelope includes those poses and finger tips and matches the earlier visible review setup. It expands culling bounds only, not geometry or gameplay collision. Owner-only visibility and disabled shadows remain intact. Recheck this envelope if the source mesh or gesture range changes. Final engine visibility must be confirmed by the root rerender.
